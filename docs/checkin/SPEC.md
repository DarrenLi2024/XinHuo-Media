# SPEC.md - 功能规格文档

## 一、核心功能模块

### 1. 用户认证系统

#### 1.1 登录功能
- **入口**：`/login` 或 `/checkin`（未登录时显示登录表单）
- **认证方式**：Token + Session 双重认证
- **默认账号**：
  - 用户名：`admin`
  - 密码：`admin123`
  - 首次登录强制修改密码
- **登录流程**：
  1. 用户提交用户名密码
  2. 后端验证并生成 Token
  3. Token 存储在 localStorage + Session 表
  4. 前端缓存用户信息

#### 1.2 权限验证
- **验证方式**：每个 API 请求携带 `Authorization: Bearer <token>`
- **后端验证**：
  1. 解析 Token
  2. 查询 Session 表验证有效性
  3. 检查用户权限
- **权限不足响应**：`{ success: false, error: '无权限执行此操作' }`

#### 1.3 密码修改
- **触发条件**：首次登录或用户主动修改
- **验证**：需要验证旧密码
- **更新后**：清除 `mustChangePassword` 标记

### 2. 签到功能

#### 2.1 扫码签到（核心功能）
- **入口**：`/checkin`
- **扫码模式**：全局键盘监听，无需聚焦输入框
- **扫码枪特征**：
  - 快速连续输入字符
  - 结束时发送 Enter 键
  - 输入速度：约 50ms/字符
- **处理逻辑**：
  ```
  1. 监听键盘事件
  2. 字符累积到缓冲区
  3. Enter 或超时触发签到
  4. 清空缓冲区
  ```
- **防并发机制**：
  - 使用数据库原子操作
  - 条件更新：`check_in_status === 0`
  - 已签到返回错误提示

#### 2.2 手动搜索签到
- **场景**：二维码损坏、扫码枪故障
- **搜索字段**：姓名、电话、单位
- **操作**：点击"手动签到"按钮
- **结果展示**：搜索结果列表，点击签到

#### 2.3 重复签到处理
- **检测**：签到时检查 `check_in_status`
- **提示**：显示已签到信息（姓名、时间）
- **选项**：
  - 补打胸牌（不更新签到时间）
  - 取消操作

#### 2.4 最近签到列表
- **显示**：最近 50 条签到记录
- **内容**：姓名、单位、身份、桌号、时间
- **交互**：
  - 点击查看详情
  - 点击补打胸牌
  - 展开/折叠列表

### 3. 胸牌打印

#### 3.1 系统打印（默认）
- **方式**：弹出打印窗口，调用浏览器打印
- **纸张规格**：63mm × 88mm（标准胸牌）
- **内容**：
  - 活动 LOGO
  - 活动名称
  - 二维码
  - 嘉宾姓名（大号字体）
  - 嘉宾身份（带颜色标签）
  - 桌号/单位
  - 签到时间

#### 3.2 ESC/POS 热敏打印
- **连接方式**：
  - **蓝牙**：Web Bluetooth API
  - **WiFi**：通过代理服务转发
  - **USB**：WebUSB API
- **协议支持**：
  - ESC/POS（标准热敏）
  - TSPL（标签打印机）
  - ZPL（Zebra 打印机）
  - PPLB（便携标签打印机）
- **配置项**：
  - 纸张宽度：50mm / 58mm / 80mm
  - 打印密度：1-10
  - 标签类型：胸牌/简约/名片

#### 3.3 NPL 静默打印
- **场景**：Windows 本地打印服务
- **配置**：
  - 打印服务 URL
  - 打印机名称
- **优势**：无需弹出窗口，自动打印

### 4. 嘉宾管理

#### 4.1 嘉宾列表
- **入口**：`/admin`
- **显示**：
  - 姓名、电话、单位、身份、桌号
  - 签到状态（未签到/已签到）
  - 签到时间
- **搜索**：关键词搜索（姓名、电话、单位）
- **筛选**：按签到状态筛选

#### 4.2 嘉宾操作
- **添加**：单个添加（填写表单）
- **编辑**：修改嘉宾信息
- **删除**：单个删除（需确认）
- **批量操作**：
  - 批量修改身份
  - 批量修改桌号
  - 批量删除

#### 4.3 嘉宾导入
- **格式**：Excel (.xlsx)
- **必填字段**：姓名
- **可选字段**：电话、单位、身份、桌号
- **处理**：
  - 自动生成二维码
  - 默认身份：普通嘉宾
  - 重复检测：按姓名+电话

#### 4.4 嘉宾导出
- **格式**：Excel (.xlsx)
- **内容**：全部嘉宾信息 + 签到状态
- **用途**：数据备份、统计分析

## 三、业务流程

### 3.1 签到流程

```
1. 扫码枪输入二维码 → 缓冲区累积字符
2. Enter 键触发 → 发送签到请求
3. 后端验证：
   - 查找嘉宾（按二维码）
   - 检查签到状态
   - 原子更新（防并发）
4. 成功响应：
   - 返回嘉宾信息
   - 记录签到日志
5. 前端处理：
   - 显示成功提示
   - 更新统计
   - 触发打印
```

### 3.2 打印流程

```
1. 签到成功 → 检查打印配置
2. ESC/POS 启用 → 连接打印机
   - 蓝牙：Web Bluetooth 连接
   - WiFi：代理服务转发
   - USB：WebUSB 连接
3. 生成打印数据：
   - ESC/POS 编码
   - 或 TSPL/ZPL 指令
4. 发送打印 → 返回结果
5. 失败兜底 → 系统打印弹窗
```

### 3.3 数据导入流程

```
1. 上传 Excel 文件
2. 解析数据行
3. 验证必填字段
4. 生成二维码
5. 检查重复
6. 批量插入数据库
7. 返回导入结果
```

## 四、特殊处理

### 4.1 并发签到处理
- **问题**：多终端同时签到同一嘉宾
- **解决**：数据库原子操作
- **SQL**：`UPDATE guests SET check_in_status=1 WHERE id=? AND check_in_status=0`
- **结果**：只有一个终端成功，其他返回"已签到"

### 4.2 长图导出颜色问题
- **问题**：Tailwind CSS v4 使用 lab() 颜色函数
- **解决**：
  - 使用内联样式 + 十六进制颜色
  - onclone 移除外部样式表
  - 遍历元素替换非标准颜色

### 4.3 XLSX 中文文件名问题
- **问题**：HTTP Header ByteString 不支持中文
- **解决**：使用纯英文文件名
